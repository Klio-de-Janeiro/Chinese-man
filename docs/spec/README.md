# Китайский Дурак — пакет спецификаций

Статус: `0.2.1-draft`

Этот каталог содержит первый формальный черновик правил и технических
контрактов для онлайн-игры «Китайский Дурак».

Первая цель проекта — сайт, на котором два или три человека могут сыграть
друг с другом. Нейросетевой агент не входит в первую версию, но архитектура
сразу отделяет игровой движок от интерфейса и сетевого сервера.

## Как читать документы

Рекомендуемый порядок:

1. `CHANGELOG.md` — посмотреть, что изменилось после согласования.
2. `docs/05_open_questions.md` — проверить журнал уже принятых решений.
3. `docs/01_rules_v1.md` — проверить полный игровой процесс.
4. `docs/04_acceptance_scenarios.md` — проверить правила на примерах.
5. `docs/02_state_machine.md` — проверить переходы между фазами.
6. `docs/03_action_and_network_protocol.md` — проверить команды сайта.
7. `docs/06_architecture_boundaries.md` — проверить границы компонентов.

## Обозначения

- `[FIXED]` — требование уже задано владельцем проекта.
- `[DECIDED]` — вариант выбран владельцем проекта при согласовании.
- `[PROPOSED]` — рекомендуемое правило, которое нужно подтвердить.
- `[OPEN]` — решение ещё не принято.
- `MUST` — обязательное поведение.
- `MUST NOT` — запрещённое поведение.
- `MAY` — допустимое, но необязательное поведение.

## Уже зафиксированные требования

- В партии участвуют два или три игрока.
- Используется колода из 52 карт.
- Первая атакующая карта может быть любой.
- Каждая следующая атакующая карта должна иметь достоинство, уже
  присутствующее среди атакующих или защитных карт на столе.
- На столе может находиться не более шести атакующих карт.
- Вместе с защитными картами на столе может находиться не более двенадцати
  карт.
- Перевод разрешён в первой версии.
- Отдельного режима без перевода нет.
- Если защитник забирает карты, он получает весь стол, включая уже побитые
  пары.
- Сначала создаётся онлайн-игра для людей. Нейросеть добавляется позднее.

## Решения версии 0.2.0

- Первым атакует владелец младшего козыря.
- Лимит атак равен минимуму из шести и начального размера руки защитника.
- После перевода лимит не увеличивается.
- Обратный перевод вдвоём разрешён.
- Проездной перевод запрещён.
- После первой защиты перевод запрещён.
- Все незащищающиеся игроки могут подкинуть без очереди.
- При одновременных попытках сервер принимает первое корректно
  зафиксированное действие.
- После новой атаки прежние пассы сбрасываются.
- После объявления «Беру» атакующие могут продолжать подкидывать.
- Добор начинается с текущего главного атакующего, защитник добирает последним.
- Все продуктовые вопросы `Q-001–Q-024` получили решения.

## Что означает «нет отдельного подкидного режима»

В текущей спецификации это означает, что пользователь не выбирает между
режимами «подкидной» и «переводной». Игра всегда переводная.

При этом возможность добавлять новые атакующие карты остаётся частью
переводной игры. Иначе правило о последующих картах с достоинствами со стола
не использовалось бы.

Если имелось в виду полное запрещение подкидывания после первой атаки, это
необходимо отдельно отметить в `docs/05_open_questions.md`.

## Правило внесения изменений

После следующего уточнения правил:

1. решение заносится в таблицу вопросов;
2. обновляется `01_rules_v1.md`;
3. добавляется или изменяется проверочный сценарий;
4. при необходимости обновляется конечный автомат;
5. версия спецификации увеличивается.

Правило не считается реализуемым, пока для него нельзя записать однозначный
проверочный сценарий.
