# Проверочные игровые сценарии

Версия: `0.2.1-draft`

Эти сценарии должны использоваться как основа unit-, integration- и
end-to-end-тестов.

## 1. Базовая атака

### S-001. Любая первая карта

Дано:

- стол пуст;
- A — главный атакующий;
- у A есть `Q♣`.

Действие:

```text
A → ATTACK(Q♣)
```

Ожидание:

- создаётся первый слот атаки;
- B становится действующим защитником.

### S-002. Допустимое достоинство атакующей карты

Дано:

```text
Стол: 7♣ / 9♣
```

У атакующего есть `7♥`, `9♠`, `K♦`.

Ожидание:

- `7♥` разрешена;
- `9♠` разрешена;
- `K♦` запрещена.

### S-003. Шесть атак

Дано:

- на столе шесть атакующих карт;
- все они побиты.

Ожидание:

- новые действия `ATTACK` отсутствуют;
- атакующим доступен только `PASS_ATTACK`.

### S-004. Запрет седьмой атаки

Любая попытка создать седьмой атакующий слот отклоняется с
`ATTACK_LIMIT_REACHED`.

## 2. Защита

### S-005. Старшая карта той же масти

```text
Атака: 8♣
Защита: J♣
```

Ожидание: защита разрешена.

### S-006. Младшая карта той же масти

```text
Атака: J♣
Защита: 8♣
```

Ожидание: защита запрещена.

### S-007. Козырь против некозыря

Козырь — червы:

```text
Атака: A♣
Защита: 2♥
```

Ожидание: защита разрешена.

### S-008. Некозырь против козыря

Козырь — червы:

```text
Атака: 6♥
Защита: A♣
```

Ожидание: защита запрещена.

### S-009. Выбор слота

Дано:

```text
slot 0: 8♣ / пусто
slot 1: Q♦ / пусто
```

Защитник играет `K♦` в `slot 1`.

Ожидание:

- `slot 1` становится побитым;
- `slot 0` остаётся непобитым.

## 3. Перевод

### S-010. Простой перевод втроём

Игроки расположены:

```text
A → B → C → A
```

Действия:

```text
A → ATTACK(7♣)
B → TRANSFER(7♥)
```

Ожидание:

- B становится главным атакующим;
- C становится защитником;
- A становится дополнительным атакующим;
- на столе две непобитые семёрки.

### S-011. Перевод неправильным достоинством

```text
Атака: 7♣
Попытка перевода: 8♥
```

Ожидание: `INVALID_TRANSFER_RANK`.

### S-012. Перевод после первой защиты

Действия:

```text
A → ATTACK(7♣)
B → DEFEND(9♣)
A → ATTACK(9♥)
```

B пытается перевести девяткой.

Ожидание: `TRANSFER_LOCKED`.

### S-013. Цепочка перевода втроём

Действия:

```text
A → ATTACK(6♣)
B → TRANSFER(6♦)
C → TRANSFER(6♥)
```

Ожидание:

- C становится главным атакующим;
- A становится защитником;
- B становится дополнительным атакующим;
- A защищается от трёх шестёрок.

### S-014. Обратный перевод вдвоём

Действия:

```text
A → ATTACK(10♣)
B → TRANSFER(10♦)
A → TRANSFER(10♥)
```

Ожидание:

- A становится главным атакующим;
- B снова становится защитником;
- на столе три десятки.

### S-015. Перевод превышает руку нового защитника

Дано:

- после перевода на столе будет три атакующие карты;
- у нового защитника две карты.

Ожидание:

- перевод запрещён;
- ошибка `NEW_DEFENDER_HAS_TOO_FEW_CARDS`.

### S-016. Карта может и бить, и переводить

Козырь — пики:

```text
Атака: 7♣
Карта защитника: 7♠
```

Ожидание:

- доступны два разных действия:
  `DEFEND(7♠)` и `TRANSFER(7♠)`;
- UI не выбирает действие автоматически.

## 4. Конкурентное подкидывание

### S-017. Оба атакующих имеют право подкинуть

При игре втроём после успешной защиты текущей атаки:

- главный и дополнительный атакующие находятся в `eligible_attackers`;
- оба могут отправить `ATTACK` или `PASS_ATTACK`;
- отдельной очерёдности нет.

### S-018. Два одновременных подкидывания

Дано:

- A и C — атакующие;
- оба видят версию `42`;
- оба отправляют допустимый `ATTACK`.

Ожидание:

- первая серверная транзакция создаёт версию `43`;
- вторая команда получает `STALE_STATE`;
- на стол добавляется только одна карта;
- проигравший гонку может повторить действие для версии `43`.

### S-019. Пас одного атакующего

Действия:

```text
A → PASS_ATTACK
```

Ожидание:

- A отмечен как пасовавший;
- C может продолжать подкидывать;
- A не может атаковать до сброса пассов.

### S-020. Все атакующие пасовали

Действия:

```text
A → PASS_ATTACK
C → PASS_ATTACK
```

Ожидание:

- стол уходит в отбой;
- начинается добор.

### S-021. Пассы сбрасываются

Действия:

```text
A → PASS_ATTACK
C → ATTACK(9♠)
```

Ожидание:

- A снова получает право подкинуть;
- прежний пас A больше не действует.

## 5. Взятие стола

### S-022. Объявление взятия частично побитого стола

Дано:

```text
slot 0: 7♣ / 9♣
slot 1: 9♥ / J♥
slot 2: J♠ / пусто
```

Защитник выбирает `TAKE`, после чего оба атакующих пасуют.

Ожидание:

- защитник получает все пять карт;
- ни одна карта не уходит в отбой;
- стол очищается.

### S-023. Добровольное взятие

Даже если у защитника есть допустимая карта защиты, действие `TAKE` разрешено.

### S-023A. Взятие накопленного отбоя

Дано:

- после успешного предыдущего раунда в отбое находятся две карты;
- в текущем раунде на столе лежит одна непобитая атакующая карта;
- защитник выбирает `TAKE`, после чего все атакующие пасуют.

Ожидание:

- сразу после принятия `TAKE` защитник получает обе карты из отбоя;
- сразу после принятия `TAKE` отбой становится пустым;
- после паса атакующих защитник получает карту текущего стола;
- после разрешения взятия стол очищается;
- инвариант 52 уникальных карт сохраняется.

### S-024. Подкидывание после взятия

Дано:

```text
slot 0: 7♣ / 9♣
slot 1: 9♥ / пусто
```

B выбирает `TAKE`. Затем C играет `ATTACK(7♠)`.

Ожидание:

- `7♠` принимается;
- карта создаёт новый непобитый слот;
- B не может защищать `7♠`;
- после паса всех атакующих B получает весь стол.

### S-025. Пассы после взятия сбрасываются

Действия:

```text
B → TAKE
A → PASS_ATTACK
C → ATTACK(9♠)
```

Ожидание:

- пас A удаляется;
- A снова может подкинуть или пасовать.

### S-026. Достигнут лимит после взятия

После `TAKE` один из атакующих добавляет шестую атакующую карту.

Ожидание:

- новая карта принимается;
- движок автоматически переходит к `RESOLVE_TAKE`;
- седьмую карту подкинуть нельзя.

## 6. Добор

### S-027. Добор до шести

После раунда у игрока четыре карты.

Ожидание: игрок получает две карты, если они есть в колоде.

### S-028. Рука больше шести

После взятия у игрока одиннадцать карт.

Ожидание: игрок не добирает и сохраняет все одиннадцать карт.

### S-029. Недостаточно карт

Игроку нужно три карты, но в колоде осталась одна.

Ожидание:

- игрок получает одну карту;
- колода становится пустой;
- следующие игроки не добирают.

## 7. Завершение

### S-030. Игрок вышел при пустой колоде

После разрешения раунда:

- колода пуста;
- рука A пуста;
- у B и C есть карты.

Ожидание:

- A получает место;
- A исключается из порядка;
- B и C продолжают вдвоём.

### S-031. Пустая рука при непустой колоде

После игрового действия рука A пуста, но в колоде есть карты.

Ожидание:

- A ещё не победил;
- во время добора A снова получает карты.

### S-032. Последний игрок

После выхода A и B у C остаются карты.

Ожидание:

- партия завершается;
- C получает результат `DURAK`.

### S-033. Одновременное завершение вдвоём

После успешного завершения раунда:

- колода пуста;
- обе руки пусты.

Ожидание: ничья.

### S-034. Одновременный выход втроём

После завершения раунда A и B одновременно выполнили условие выхода.

Ожидание:

- A и B получают одинаковое `placement`;
- оставшийся C получает `isDurak = true`.

## 8. Сеть и конкурентность

### S-035. Двойной клик одного игрока

A дважды быстро нажимает одну карту.

Ожидание:

- только одна команда изменяет состояние;
- повтор получает `DUPLICATE_ACTION` или `STALE_STATE`;
- карта не дублируется.

### S-036. Устаревший клиент

Клиент отправляет:

```text
expectedVersion = 17
```

А сервер уже хранит версию `18`.

Ожидание:

- действие не применяется;
- клиент получает `STALE_STATE`;
- сервер отправляет snapshot версии `18`.

### S-037. Переподключение

Игрок отключился на фазе защиты и подключился снова.

Ожидание:

- он занимает прежнее место;
- получает собственную руку;
- получает актуальное состояние;
- другие игроки не получают его карты.

### S-038. Истечение окна переподключения

Игрок не вернулся в течение 120 секунд.

Ожидание:

- ему засчитывается техническое поражение;
- сервер не играет карты от его имени;
- результат сохраняется.

### S-039. Попытка сыграть чужой картой

Клиент вручную отправляет `cardId`, которого нет в его руке.

Ожидание: `CARD_NOT_IN_HAND`, состояние не изменяется.

## 9. Инварианты

### S-040. Сохранение карт

После каждого принятого действия:

```text
руки + колода + стол + отбой = 52 уникальные карты
```

### S-041. Доступное действие

В любой фазе, требующей решения:

- `OPENING_ATTACK` имеет хотя бы одну атаку;
- `DEFENSE` имеет `TAKE`;
- `ATTACK_EXTENSION` имеет `PASS_ATTACK` для каждого непасовавшего
  атакующего;
- `THROW_AFTER_TAKE` имеет `PASS_ATTACK` для каждого непасовавшего
  атакующего.

Пустой список действий считается ошибкой движка.

## 10. Зафиксированные решения

### S-042. Первый атакующий по младшему козырю

Начальные руки содержат:

```text
A: 8♥
B: 3♥
C: без козырей

Козырь: ♥
```

Ожидание: первым атакует B.

### S-043. В начальных руках нет козырей

Дано:

- ни у одного игрока нет козыря;
- сдающий — A.

Ожидание: первым атакует следующий игрок B.

### S-044. Лимит по начальной руке защитника

В начале раунда у защитника три карты.

Ожидание:

```text
attack_limit = min(6, 3) = 3
```

Четвёртая атакующая карта запрещена.

### S-045. Перевод не увеличивает лимит

Дано:

- текущий `attack_limit = 3`;
- после перевода у нового защитника шесть карт.

Ожидание: `attack_limit` остаётся равен трём.

### S-046. Перевод уменьшает лимит

Дано:

- текущий `attack_limit = 6`;
- после перевода у нового защитника четыре карты;
- на столе не более четырёх атак.

Ожидание: новый `attack_limit = 4`.

### S-047. Проездной перевод запрещён

Защитник показывает козырную карту нужного достоинства, но пытается оставить
её в руке.

Ожидание:

- действие отсутствует в `legalActions`;
- состояние не изменяется.

### S-048. Порядок добора после перевода

После перевода:

```text
B — главный атакующий
A — дополнительный атакующий
C — защитник
```

Ожидание:

```text
порядок добора: B → A → C
```
